## Delivery discipline

For every behaviour: write one failing acceptance, contract, integration or concurrency test; run it and confirm the expected failure; add the smallest production code that passes; run the focused test; then run the full suite, lint, type check and build. Tests describe the accepted behaviour and take precedence over implementation convenience.

No section receives a “complete” status based solely on a happy path. Financial, inventory, authorization and admission sections require their documented failure, replay and concurrency cases before the next dependent section begins.

## Module 5 payment contract

- `POST /orders/:orderReference/payments` creates a server-generated Paystack attempt and returns only its reference, authorization URL, and access code. It never exposes the Paystack secret or sends split/subaccount/transfer fields.
- `POST /webhooks/paystack` keeps the original request bytes, validates `x-paystack-signature`, and responds with HTTP 200 only after the signed `charge.success` reference has followed server-side verification.
- `POST /orders/:orderReference/reconcile` is the guest-safe browser return/callback route. It uses the server-generated high-entropy order reference and only asks Paystack to verify the latest initialized attempt. The legacy payment-reference route remains customer-session protected.
- `npm run worker` runs reconciliation immediately and then at `PAYMENT_RECONCILIATION_INTERVAL_MS` (five minutes by default). The worker needs `DATABASE_URL` and `PAYSTACK_SECRET_KEY`.

## Current database configuration

The local PostgreSQL database `EveryTicket` is available through the credentials in the separate dashboard-backend environment file. EverythingTicket derives a local `DATABASE_URL` only in the process that runs its Prisma migration or integration test; it does not alter dashboard-backend's configured `DBDATABASE` value. This keeps the two applications' databases separate.

For hosted environments, set `DATABASE_URL` directly in the service environment as shown in `.env.example`; do not depend on a sibling project's environment file.
